PART 1: RUNNING LOCALLY (DEVELOPMENT MODE WITH LIVE CHANGES)
--------------------------------------------------------------------------------

1. PREREQUISITES
   - Node.js v20+ and npm installed
   - Docker Desktop running (for local PostgreSQL database)

2. START LOCAL DATABASE (POSTGRESQL ONLY)
   In your root project directory:
   > npm run docker:postgres

   To verify it is running:
   > docker ps
   (You should see 'aegis-postgres' running healthy on port 5434)

3. DATABASE SYNCHRONIZATION (DDL & DML)
   - AUTOMATIC: When you pull updates from Git on any machine and run:
     > npm run dev:backend
     It automatically detects and applies all schema changes (`prisma db push`),
     generates Prisma client bindings, and synchronizes system roles,
     permissions, and catalog seed data (DML).
   - MANUAL (Optional): You can manually trigger full sync anytime with:
     > npm run db:sync

4. START BACKEND (NestJS with live code reloading)
   Open Terminal 1 (or run this in current terminal to load Node/npm):
   > $env:PATH = "C:\Users\tanoy\AppData\Roaming\fnm\node-versions\v20.20.2\installation;" + $env:PATH
   > npm run dev:backend
   - Backend URL: http://localhost:3000/api/v1
   - Automatically executes DB schema & DML sync before launching.
   - Watches apps/backend/src for live code changes.

5. START FRONTEND (Next.js with Fast Refresh)
   Open Terminal 2:
   > npm run dev:frontend
   - Frontend URL: http://localhost:3001
   - Watches apps/frontend for UI changes automatically.

6. FIRST-TIME INITIALIZATION & USER CREATION GOVERNANCE
   - First-Time Fresh Setup:
     If the database has zero users (e.g. freshly created production database),
     the Login Page (http://localhost:3001/login) automatically displays the
     "Initial System Setup" form allowing you to create the initial Super Admin
     and set their password.
   - User Protection Rule:
     Once ANY user exists in the database, the "Create User" form & button
     disappears permanently from the login page.
   - Provisioning New Users:
     All future doctors, cashiers, nurses, and staff can ONLY be provisioned
     from within the system by the Super Admin via the Employee / HR / IAM module.

7. DEMO LOGIN CREDENTIALS (When using seeded database)
   - Super Admin:     admin@aegis.health       / Admin@123456
   - Doctor (Metro):  dr.marcus@aegis.health   / Staff@123456
   - Cashier (Metro): cashier.metro@aegis.health / Staff@123456
   - Doctor (West):   dr.sarah@aegis.health    / Staff@123456

8. STOPPING LOCAL SERVICES
   - Stop Frontend/Backend: Press Ctrl + C in their respective terminal windows.
   - Stop PostgreSQL Docker:
     > npm run docker:down

PART 2: CONFIGURATION & STEPS FOR DEPLOYING ON A VPS SERVER (Ubuntu/Debian)
--------------------------------------------------------------------------------

1. MINIMUM VPS SPECIFICATIONS
   - OS: Ubuntu 22.04 LTS or Ubuntu 24.04 LTS (recommended)
   - CPU: 2 vCPUs minimum
   - RAM: 4 GB minimum (2 GB with 2GB swap space)
   - Storage: 30 GB+ SSD

2. DOMAIN & DNS SETUP (Point DNS before generating SSL)
   - Point your root domain or subdomain to your VPS Public IP address:
     * yourclinic.com       ->  A Record ->  [YOUR_VPS_IP]
     * api.yourclinic.com   ->  A Record ->  [YOUR_VPS_IP] (Optional if using subpaths)

3. INITIAL SERVER SETUP & SECURITY
   SSH into your VPS:
   > ssh root@YOUR_VPS_IP

   Update packages:
   > sudo apt update && sudo apt upgrade -y

   Configure basic firewall (UFW):
   > sudo ufw allow OpenSSH
   > sudo ufw allow 80/tcp
   > sudo ufw allow 443/tcp
   > sudo ufw enable

   Install Docker and Docker Compose plugin:
   > sudo apt install -y ca-certificates curl gnupg
   > sudo install -m 0755 -d /etc/apt/keyrings
   > curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
   > sudo chmod a+r /etc/apt/keyrings/docker.gpg
   > echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
   > sudo apt update
   > sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

4. CLONE THE REPOSITORY ON YOUR VPS
   > cd /home/tny/source
   > git clone <YOUR_GIT_REPO_URL> health-center-management-system
   > cd health-center-management-system

5. PRODUCTION ENVIRONMENT CONFIGURATION (.env)
   Create your production environment file:
   > nano .env

   Provide strong production secrets (NEVER use defaults):
   -----------------------------------------------------------------------------
   # Database (Internal Docker network communication)
   POSTGRES_USER=aegis_prod_user
   POSTGRES_PASSWORD=GENERATE_STRONG_RANDOM_PASSWORD_HERE
   POSTGRES_DB=aegis_his_production
   DATABASE_URL=postgresql://aegis_prod_user:GENERATE_STRONG_RANDOM_PASSWORD_HERE@postgres:5432/aegis_his_production?schema=public

   # Redis
   REDIS_PASSWORD=GENERATE_ANOTHER_RANDOM_PASSWORD_HERE
   REDIS_URL=redis://:GENERATE_ANOTHER_RANDOM_PASSWORD_HERE@redis:6379

   # Authentication Secret
   JWT_SECRET=GENERATE_A_64_CHARACTER_RANDOM_SECRET_KEY
   JWT_EXPIRATION=1d

   # Ports
   BACKEND_PORT=4000
   FRONTEND_PORT=3001

   # Frontend Subpath & Public API URL (Proxied by Nginx)
   NEXT_PUBLIC_BASE_PATH=/health-erp
   NEXT_PUBLIC_API_URL=/health-erp/api/v1
   -----------------------------------------------------------------------------

6. DEPLOY USING DOCKER COMPOSE ON VPS
   Run all services (PostgreSQL with pgvector, Redis, NestJS Backend, Next.js Frontend):
   > docker compose -f docker-compose.prod.yml up -d --build

   Apply database migrations and initial seed on first deployment:
   > docker compose -f docker-compose.prod.yml exec backend npx prisma migrate deploy
   > docker compose -f docker-compose.prod.yml exec backend npm run prisma:seed

7. CONFIGURE NGINX REVERSE PROXY FOR TRIPLE HOSTING
   Host Nginx proxies all three projects seamlessly:
   - Portfolio on '/' (port 3000)
   - Health Center ERP on '/health-erp' (port 3001) & API on '/health-erp/api/' (port 4000)
   - AutoApply AI on '/autoapply' (port 3002) & API on '/autoapply/api/' (port 8000)

   Edit your Nginx site configuration:
   > sudo nano /etc/nginx/sites-available/default

   Paste the unified configuration:
   -----------------------------------------------------------------------------
   server {
       listen 80;
       server_name 139.59.125.139; # Replace with your domain when ready

       client_max_body_size 50M;

       # ----------------------------------------------------
       # 1. AUTOAPPLY AI BACKEND API (FastAPI on port 8000)
       # ----------------------------------------------------
       location /autoapply/api/ {
           proxy_pass http://127.0.0.1:8000/api/;
           proxy_http_version 1.1;
           proxy_set_header Upgrade $http_upgrade;
           proxy_set_header Connection 'upgrade';
           proxy_set_header Host $host;
           proxy_cache_bypass $http_upgrade;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
           proxy_read_timeout 300s;
       }

       # ----------------------------------------------------
       # 2. AUTOAPPLY AI FRONTEND (Next.js on port 3002)
       # ----------------------------------------------------
       location /autoapply {
           proxy_pass http://127.0.0.1:3002;

           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
       }

       # ----------------------------------------------------
       # 3. HEALTH ERP BACKEND API (NestJS on port 4000)
       # ----------------------------------------------------
       location /health-erp/api/ {
           proxy_pass http://127.0.0.1:4000/api/;
           proxy_http_version 1.1;
           proxy_set_header Upgrade $http_upgrade;
           proxy_set_header Connection 'upgrade';
           proxy_set_header Host $host;
           proxy_cache_bypass $http_upgrade;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
       }

       # ----------------------------------------------------
       # 4. HEALTH ERP FRONTEND (Next.js on port 3001)
       # ----------------------------------------------------
       location /health-erp {
           proxy_pass http://127.0.0.1:3001;
           proxy_http_version 1.1;
           proxy_set_header Upgrade $http_upgrade;

       }

       # ----------------------------------------------------
       # 5. PORTFOLIO SITE (Next.js on port 3000)
       # ----------------------------------------------------

           proxy_pass http://127.0.0.1:3000;
           proxy_http_version 1.1;
           proxy_set_header Upgrade $http_upgrade;
           proxy_set_header Connection 'upgrade';

       }
   }
   -----------------------------------------------------------------------------

   Test and reload Nginx:
   > sudo nginx -t
   > sudo systemctl reload nginx

8. SHARED POSTGRESQL DATABASE ARCHITECTURE (Multi-Schema)
   - PostgreSQL runs in container 'aegis-prod-postgres' on 'aegis_internal_network' (port 5432).
   - Health Center ERP tables reside in schema 'public'.
   - AutoApply AI tables reside in schema 'job_automation'.
   - Database extensions (pgvector, uuid-ossp) reside in 'public' and are shared.
   - Zero duplicate database processes or memory bloat.

9. AUTOMATED DATABASE BACKUP SETUP (Cron Job)
   Set up daily automated PostgreSQL backups:
   > sudo crontab -e
   Add this line (runs daily at 2:00 AM):
   0 2 * * * docker compose -f /home/tny/source/health-center-management-system/docker-compose.prod.yml exec -T postgres pg_dump -U aegis_prod_user aegis_his_production > /var/backups/aegis_$(date +\%F).sql

10. CI/CD AUTO-DEPLOYMENT
   Automated GitHub Actions deploy on push to prod:
   > git push origin prod
